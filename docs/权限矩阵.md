# 权限矩阵（RBAC）— 前端对接方案

> 后端 JWT 含 `role` claim（`student` / `assistant` / `teacher` / `admin`），前端按角色显示 UI；后端按角色 + 数据属主校验，前端 UX 不替代后端权限。

## 角色

| 角色 | 定位 |
| --- | --- |
| student | 学生：提交作业、看自己提交/诊断/变式/成绩 |
| assistant | 助教：本班评改与申诉初审 |
| teacher | 教师：本课命题/评改/学情/申诉终审/反作弊 |
| admin | 教务/管理：全校脱敏看板、审计、系统配置 |

## 数据权限规则

- **teacher**：操作 course/class/assignment/学情/成绩/申诉/反作弊时校验 `course.teacher_id == user.id`（资源属主）。
- **student**：提交作业校验选课（enrollment：选了 `assignment.course` 的某 class）；看 submission/诊断/变式/成绩校验 `submission.user_id == user.id`（自己）。
- **assistant**：本班（class）范围评改/申诉初审（class 属 course，course 属 teacher）。
- **admin**：全校 + 审计 + 配置。

## 后端守卫依赖（`app/core/deps`）

- `get_current_user`：任意登录
- `require_student` / `require_assistant` / `require_teacher` / `require_admin`：单角色
- `require_staff`：teacher | assistant | admin（评改类）

## 前端配合

- 登录后读 JWT `role`，按角色渲染菜单/页面（学生看提交/诊断/变式/成绩；教师看命题/学情/申诉/反作弊/成绩册；教务看全校看板/审计）。
- 数据权限失败后端返 `403 forbidden`，前端提示「无权访问」。

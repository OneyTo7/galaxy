## 一、作品概述

面向高校编程、AI、数据类课程的实验教学平台。除了常见的「自动出题、自动评测」，重点是它还能看出**学生错在哪、卡在哪类思路上**，并给出针对性的练习，同时把成绩、申诉、反作弊这些教学里绕不开的事也管理起来。

- **一句话定位**：从「判对错」升级到「洞察学生怎么错、卡在哪个点」，并给出针对性变式练习的院校级实验教学平台。
- **核心痛点**：
  1. 老师出题、批改、答疑很占时间，且通常只看到「学生这题错了」，看不到为什么会错、卡在哪个点；
  2. 编程、AI 课学生多，助教不够，很难逐个答疑、逐个盯进度；
  3. 市面平台大多停在「判分 + 答疑」，说不清学生具体哪里没掌握，也管不好成绩与反作弊。
- **目标用户与场景**：高校编程 / AI / 数据课程的实验教学；面向 985/211、普通本科、高职各类院校，优先从「最需要、最容易上手」的院校（如刚开 AI 通识课的院校）试点，再逐步推广。
- **核心亮点**（不超过 3 条）：
  1. 解释性误区诊断——输出「误区类型 + 证据 + 对应知识点」，而非只给标准答案；
  2. 动态变式练习——按学生自己的误区实时生成换情境的变式题，对症下药；
  3. 院校级一体化——沙箱安全、严格判定、成绩申诉、反作弊 / 合规一条龙，能真开课用。

> 定位上不是只能展示的原型，而是「放在学校里真的能开课用」的工具。出题、判分、查重照做作为底子，但不算亮点。

## 二、创新性

### 2.1 创新点

**① 解释性误区诊断**
让模型读学生提交的代码，结合编译 / 运行报错与用例通过情况，做结构化归因，判断出具体误区——比如总忘记边界条件、混淆变量作用域、把赋值当比较、数组越界、类型混淆。普通平台告诉你「你错了」，我们告诉你「你是怎么错的、卡在哪个点上」。

- 诊断输出必须包含三要素：**误区类型 + 证据（具体代码行 / 报错）+ 对应知识点**，避免做成表面功夫或泛泛而谈。
- 用报错与用例结果做事实校验，约束模型输出，降低幻觉。

**② 动态变式练习**
根据诊断出的误区，现场生成一个换了情境的变式题来专门练这个点，而不是从静态题库里随便抽一道类似的题。例：同一个「数组越界」误区，换成「矩阵遍历」「链表遍历」等不同情境再练一遍。

### 2.2 技术路线原创性

- 主链路「命题 → 沙箱提交 → 严格评测 → 误区诊断 → 变式练习 → 班级学情」全流程 AI 贯穿、闭环自动化，而非各环节孤立。
- 诊断与变式基于移动云 MoMA 大模型，结合**事实校验（报错 / 用例结果）**做结构化归因，而非纯文本生成。

### 2.3 与已有方案 / 竞品差异

| 维度 | 普通 OJ（力扣 / PTA / 校内 OJ） | AI 答疑产品 | 本平台 |
| --- | --- | --- | --- |
| 判对错 / 隐藏用例 | ✅ | ✖ | ✅ |
| 认知误区诊断（类型+证据+知识点） | ✖ | 部分（问答式） | ✅ 结构化 |
| 动态变式练习 | ✖ | ✖ | ✅ |
| 班级学情图谱 / 预警 | 浅 | ✖ | ✅ |
| 成绩 / 申诉 / 反作弊 / 合规 | 弱 | ✖ | ✅ 院校级 |
| 沙箱安全执行 | 部分 | ✖ | ✅ |

> 出题、判分、查重大家都有，不算差异化；差异化在于「诊断 + 变式 + 院校级一体化」。

## 三、湛卢原生 IDE 能力运用

全流程使用湛卢原生 IDE 开发，模型调用走移动云 MoMA，部署用云主机。逐项说明「用了什么能力、用在什么环节、解决了什么问题」。

- **代码智能生成**：项目脚手架、评测引擎、诊断服务、变式生成、前端组件由 IDE 代码生成起步，显著降低重复劳动。
- **智能调试**：评测与诊断链路排错、沙箱安全问题的定位（资源限制、越权、死循环）。
- **代码评审**：对评测判分、评分细则、沙箱隔离、权限矩阵等关键模块做评审，保证严谨性。
- **单元测试 / Bug 修复**：评测判分、评分细则、作业 / 提交 / 申诉状态机等核心逻辑有单测覆盖、可回归。
- **高阶功能（Skill / MCP / 自定义流程）**：
  - **Skill**：命题评测 Skill（一句话出题 → 生成题面 + 隐藏用例 + 评分细则 + 参考实现）、诊断 Skill（结构化归因模板）。
  - **MCP**：接对象存储（题目 / 附件 / 报告）、接 MoMA 模型、接沙箱执行环境。
  - **自定义流程**：编排「命题 → 评测 → 诊断 → 变式」端到端教学流程。
- **可复用开发范式**：沉淀「评测 + 认知诊断 + 变式」的教学后端范式，可复用于其他课程与院校，形成可复制开发范式（对应加分项）。

## 四、技术实现

### 4.1 系统架构

```
Web 前端 ( Vue 3 )
   │  在线编辑器 / 提交 / 学情看板 / 误区分布图 / 管理后台
   ▼
平台后端 ( FastAPI / Python，模块化单体 + DDD 限界上下文 )
   ├─ 用户与权限          用户 / 角色 / 课程 / 班级 / 权限 (RBAC)
   ├─ 课程与作业          作业 / 用例 / 评分细则 / deadline / 状态机
   ├─ 评测引擎            判分 / 评分细则 / 隐藏用例 / 超时 / 并发调度
   ├─ 沙箱执行            Docker 隔离代码执行 (资源/网络/文件受限)
   ├─ 诊断 / 变式 / 命题   模块内调 MoMA：结构化归因 / 变式生成 / 一句话出题
   ├─ 学情报告            班级 / 课程 / 全校看板，成绩导出
   ├─ 申诉与审计          申诉状态机 / 人工复核 / 审计日志
   └─ 反作弊              AI 代写检测 / 查重 / 过程异常识别
   │
   ▼
移动云底座：MoMA 模型 · 对象存储 · 云主机 (部署演示)
```

### 4.2 技术栈与选型理由

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 后端 | FastAPI / Python（模块化单体 + DDD） | 全栈统一 Python，团队共栈协同；AI 生态顺手；契合 AI Coding 赛题用 AI 助手高效产出 |
| 模型 | 移动云 MoMA（OpenAI 兼容） | 赛题指定模型，诊断 / 变式 / 命题模块内 httpx 调用 |
| 前端 | Vue 3 + TypeScript | 团队熟悉；类型安全 + 可维护性，适合看板 / 图表（误区分布、学情画像） |
| 执行 | 安全沙箱（Docker 隔离） | 隔离学生代码，防恶意代码 / 死循环 / 越权 / 资源耗尽 |
| 数据 | PostgreSQL + Redis + 对象存储 | 结构化存用户 / 题目 / 用例 / 报告；Redis 评测队列；对象存储存附件 / 提交快照 |
| 部署 | 云主机 Docker Compose | 赛题要求云主机部署演示，可校级上云 |

### 4.3 核心数据模型

- 账号与组织：`User` / `Role` / `Course` / `Class` / `Enrollment`
- 命题：`Assignment` / `TestCase`（含隐藏用例、权重）/ 评分细则
- 提交评测：`Submission` / `Evaluation`（用例逐条结果、得分）
- 诊断与练习：`Misconception`（误区类型 + 证据 + 知识点）/ `VariantExercise`（变式题）
- 教学管理：`Grade` / `Appeal`（申诉）/ `CheatingReport` / `AuditLog`

### 4.4 关键链路

```
命题(一句话) → 作业发布 → 学生沙箱提交 → 评测判分(隐藏用例+边界+超时)
   → 误区诊断(结构化归因) → 变式生成 → 学情聚合 → 教师干预 → 申诉复核
```

**评测引擎要点**：隐藏用例 + 边界用例 + 超时 / 内存判定，不「过了样例就算对」；用例权重与评分细则支持部分分；并发调度走队列 + 限流，避免沙箱被打满。

**诊断链路要点**：输入 = 学生代码 + 编译 / 运行报错 + 用例通过情况；输出 = 误区类型 + 证据 + 知识点；用报错与用例结果做事实校验，约束模型、降低幻觉。

### 4.5 权限与状态机

- **权限矩阵**（节选）：学生仅看自己提交 / 成绩 / 诊断；助教（受授权）本班评改与申诉初审；教师本课命题、评改、申诉终审、看反作弊报告；教务 / 管理全校脱敏看板与系统配置 / 配额 / 审计。
- **作业状态机**：草稿 → 已发布 → 进行中 → 已截止 → 评测 / 评分中 → 成绩已发布 → 已归档。
- **提交状态机**：待评测 → 评测中 → 已完成(自动判) → 待人工复核。
- **申诉状态机**：已提交 → 处理中 → 已处理（改分 → 更新成绩 → 通知学生）。

### 4.6 工程完成度与分期

- **一期（主链路，优先跑通）**：智能命题 → 沙箱提交 → 严格评测 → 误区诊断 → 变式练习 → 班级学情报告。
- **二期（底线与增强）**：反作弊 / AI 代写检测、申诉复核、成绩管理增强、跨课程质量看板、审计与隐私合规。
- **部署验证**：云主机部署，在真实课程试点验证主链路可用性（对应加分项「真实业务场景部署验证」）。

## 五、应用价值

- **领域实用价值**：解决高校编程 / AI 课程「老师看不到学生怎么错、助教不够、平台太浅」的真实问题；从「看对错」到「看见怎么错」，教学更有针对性。
- **落地可行性**：云主机部署、校级上云；沙箱与严格判定保证安全与严谨；具备跨课程、跨院系复用能力。落地从最需要的院校试点、逐步推广，部署成本低、周期短。
- **市场前景**：AI 通识课正在各类高校铺开（985/211、普通本科、高职），需求面广、可复制性强；对清北这类有自研系统的名校未必刚需，但对绝大多数高校是现成可用的工具。
- **可量化对比**：答辩时用数字对照讲「用了 AI 比原来省多少时间」（出题、批改、答疑工时下降；学情洞察即时化）。

## 附：开发节奏与风险控制

- **开发节奏**：先跑通主链路（一期），再做反作弊 / 申诉 / 合规（二期）。
- **答辩要点**：为什么必须用湛卢；误区诊断的创新点；用什么保证可靠（沙箱、严格判定、反作弊）；目标院校与可推广性；AI 节省工时的量化对照。
- **要避免的问题**：
  - 只做「判题 + 答疑」，太普通，体现不出创新；
  - 误区诊断做成表面功夫，必须给出「误区类型 + 依据 + 知识点」；
  - 忽略沙箱安全与判定严谨性，这是最易被质疑的点；
  - 演示数据造假。
